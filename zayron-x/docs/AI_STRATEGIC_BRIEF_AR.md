# الدليل الاستراتيجي العربي و البرومبت الرئيسي لـ ZAYRON-X

> المرجع المصدر: `docs/reference/ZAYRON-X_MASTER_ENGINEERING_SPECIFICATION_v1.1.pdf`  
> العقد التشغيلي الملزم داخل المستودع: `docs/AI_MASTER_SPECIFICATION.md`  
> هذه الوثيقة موجهة للمالك البشري ولكل وكيل أو نموذج ذكاء اصطناعي يعمل على المشروع.

## 1. القرار المعماري غير القابل للتفاوض

ZAYRON-X منصة استخبارات وعمليات أمن سيبراني ذات مستوى مؤسسي، وليست موقع محتوى تقليديا. Cloudflare هي طبقة الدخول والتنفيذ والتشغيل الأساسية للمشروع: DNS، WAF، الحماية من الهجمات، التوجيه، الـ edge runtime، النشر، التخزين المؤقت، المراقبة، وإدارة الأسرار التشغيلية.

لا يجوز تقديم Cloudflare كخيار ثانوي أو كـ CDN فقط. أي تصميم جديد يجب أن يبدأ من السؤال التالي: "كيف ينفذ هذا بأمان وموثوقية على Cloudflare؟". الخادم التقليدي أو VPS، عند وجوده، استثناء مؤقت وموثق وليس مركز النظام.

## 3. المعمارية المستهدفة

```text
المستخدم / المحلل / النظام الخارجي
              |
      Cloudflare DNS + WAF + Rate Limits
              |
      Cloudflare Worker + OpenNext
       |          |           |
  KV / Cache   R2 / Logs    D1 / بيانات Edge محددة
       |          |           |
       +----------+-----------+
                  |
        Supabase: Auth + Postgres + RLS
                  |
      مصادر استخبارات / APIs / AI Providers
```

التفسير التشغيلي:

- Cloudflare Workers هو وقت التشغيل الافتراضي لكل endpoint أو webhook أو مهمة خفيفة قابلة للتنفيذ على الحافة.
- OpenNext هو مسار تشغيل Next.js داخل Cloudflare، وليس مجرد خيار نشر بديل.
- KV يستخدم للـ ISR، الاستجابات المخبأة، الرايات التشغيلية، والحالات القصيرة التي تقرأ كثيرا.
- R2 يستخدم للأرشيفات، تقارير SITREP المصدرة، سجلات Logpush، وملفات النسخ الاحتياطي؛ لا يوضع فيه سر أو مصدر بيانات غير محمي.
- D1 يستخدم فقط عندما يكون امتلاك بيانات علائقية قرب الـ edge مبررا ومحددا، وليس نسخة عشوائية من Supabase.
- Supabase يحتفظ بالهوية، PostgreSQL، RLS، والبيانات التطبيقية التي تحتاج معاملات أو استعلامات غنية.
- أي اتصال إلى خدمة خارجية يمر عبر سياسة أسرار ومهلات وretry ومراقبة ورقابة وصول.

## 4. أولويات التعديل في الكود والوثائق

### الأولوية 0: منع الانحراف المعماري

1. قبل تعديل أي ميزة، يقرأ الوكيل `AGENTS.md` ثم `docs/AI_MASTER_SPECIFICATION.md` ثم هذه الوثيقة.
2. استبدال أي تعليمات تشغيلية تجعل PM2 أو Nginx أو VPS نقطة التشغيل العادية بتعليمات Cloudflare Workers وWrangler وCloudflare Dashboard/API.
3. الإبقاء على VPS فقط إذا كان هناك قيد تقني مثبت لا يمكن تنفيذه في Workers؛ يوثق السبب والمالك وخطة الإزالة وتاريخ المراجعة.

### الأولوية 1: تثبيت عقد Cloudflare

1. تدقيق `wrangler.toml` و`open-next.config.ts` و`worker-wrapper.js` معا في كل تغيير نشر.
2. إنشاء قائمة bindings موثقة: الاسم، النوع، البيئة، المالك، البيانات المسموحة، وخطة الاستعادة.
3. إبقاء الأسرار في Cloudflare Secrets أو مدير أسرار معتمد فقط. لا تكتب في `.env.example` قيما حقيقية ولا تكررها في ملفات Markdown.
4. ربط deploy preview وproduction بتحقق build واختبارات صحة وrollback واضح.

### الأولوية 2: خط بيانات الاستخبارات والذكاء الاصطناعي

1. فصل ingestion عن العرض: جمع المصدر، التحقق، التطبيع، إزالة التكرار، التحليل، ثم النشر.
2. جعل كل مخرج AI قابلا للتدقيق: المصدر، الوقت، النموذج/الإصدار، مستوى الثقة، وقرار المراجعة البشرية.
3. منع النشر التلقائي للادعاءات الأمنية عالية الأثر دون عتبة ثقة ومراجعة.
4. استخدام queue أو cron في Cloudflare للمهام المؤجلة والمتكررة، بدلا من daemon دائم على VPS متى كان ذلك ممكنا.

### الأولوية 3: تجربة Premium مع الحفاظ على الألوان

1. لا تغير لوحة الألوان الأساسية أو هوية ZAYRON-X إلا بموافقة صريحة.
2. ارفع القيمة البصرية عبر طبقات عميقة، تباين مضبوط، مساحات بيضاء مقصودة، حدود دقيقة، وبيانات ذات معنى؛ لا عبر مؤثرات زائدة أو تدرجات عشوائية.
3. اجعل الواجهة تشبه غرفة عمليات استخبارات مؤسسية: هادئة، حادة، موثوقة، سريعة القراءة، وليست dashboard مزدحمة أو قالب SaaS جاهزا.
4. كل شاشة يجب أن تجيب بوضوح: ما الخطر؟ ما السياق؟ ما درجة الثقة؟ ما الإجراء التالي؟
5. احترم RTL والعربية بمستوى متساو مع الإنجليزية، مع خطوط وتسلسل بصري ومكونات لا تنكسر على الهاتف.

## 5. معايير قبول أي تغيير

لا يعتبر التغيير مكتملًا ما لم يثبت أنه:

- يعمل على مسار Cloudflare-first أو يوثق استثناءه بدقة.
- لا يضيف سرا أو صلاحية زائدة أو تجاوزا لـ RLS/CSP/rate limits.
- لا يسبب تعارضا بين `wrangler.toml` وOpenNext والكود.
- يملك مراقبة أو logging مناسبين للحالات الحساسة.
- يحافظ على الأداء على الهاتف وسهولة الوصول والـ RTL.
- يحدث الوثائق حين يغير الحقيقة التشغيلية.
- يشرح بوضوح ما تغير، سبب التغيير، المخاطر، وخطة rollback عند الحاجة.

## 6. البرومبت الرئيسي الإلزامي لأي ذكاء اصطناعي

انسخ النص التالي كاملا عند تكليف أي نموذج ذكاء اصطناعي بالعمل على المشروع. أرفق معه ملف PDF المرجعي أو اذكر مساره داخل المستودع.

```text
أنت الوكيل الهندسي المسؤول عن مشروع ZAYRON-X. يجب أن ترد بالعربية الواضحة، وأن تكون دقيقا وصريحا ولا تفترض حقائق غير مؤكدة.

المراجع الإلزامية بترتيب الأولوية:
1) ملف PDF: ZAYRON-X_MASTER_ENGINEERING_SPECIFICATION_v1.1.pdf.
2) docs/AI_MASTER_SPECIFICATION.md.
3) AGENTS.md.
4) الكود وإعدادات البنية الحالية، خصوصا wrangler.toml وopen-next.config.ts وworker-wrapper.js.
5) الوثائق التشغيلية الحالية.

قاعدة الحوكمة:
لا تنفذ أي قرار معماري أو تعديل كود أو إعداد نشر قبل قراءة المراجع السابقة ومقارنة الطلب بها. إذا تعارض طلب مع هذه المراجع، أوقف التنفيذ واشرح التعارض والحل المتوافق. لا تخترع بنية أو خدمة أو مسار نشر خارج هذه الحدود.

العقيدة المعمارية:
Cloudflare هي المصدر التشغيلي الأساسي والكامل للمنصة: DNS، الحماية، WAF، Rate Limiting، edge routing، Workers runtime، OpenNext deployment، caching، observability، Cron، وعمليات النشر والـ rollback. لا تعامل Cloudflare كـ CDN فقط ولا تجعلها مسارا اختياريا في نقطة حرجة.

ترتيب التنفيذ المسموح:
- Cloudflare Workers وOpenNext أولا.
- Cloudflare KV وR2 وD1 وWorkers Assets وCron وObservability ثانيا.
- Supabase للمصادقة وPostgres وRLS والبيانات التي تحتاجها هذه الطبقة.
- Redis أو خدمة خارجية فقط عند وجود تبرير تقني واضح وآمن على edge.
- VPS وPM2 وNginx استثناء legacy فقط؛ لا تضفها ولا تبن عليها ميزة جديدة إلا عندما تقدم دليلا أن Workers غير مناسبة، مع توثيق خطة إزالة الاستثناء.

قواعد منع مطلقة:
- ممنوع تخزين الأسرار أو المفاتيح أو tokens في الكود أو Markdown أو ملفات البيئة الملتزمة في Git.
- ممنوع تعطيل أو تجاوز RLS أو CSP أو المصادقة أو rate limits لتسهيل التنفيذ.
- ممنوع إضافة endpoint حساس دون authorization وvalidation وlogging وحدود زمنية واضحة.
- ممنوع تحويل المنصة إلى تصميم SaaS عام، أو تغيير ألوانها الأساسية دون موافقة صريحة.
- ممنوع تنفيذ مخرجات AI عالية الأثر أو نشرها بلا مصدر ومستوى ثقة ومراجعة بشرية عند الحاجة.
- ممنوع تقديم VPS كحل افتراضي أو جعل Cloudflare طبقة ثانوية.

منهج العمل الإلزامي في كل مهمة:
1) اقرأ المراجع، ثم افحص الملفات ذات الصلة فعليا.
2) قدم تقريرا عربيا قصيرا قبل التعديل: أين نحن؟ ما المطابق؟ ما الفجوة؟ ما الملفات التي ستتغير؟ وما المخاطر؟
3) اقترح أصغر تعديل متين يحرك المشروع نحو المواصفات، ولا تغير ملفات غير مرتبطة.
4) نفذ التعديل مع الالتزام بالأنماط الحالية في المشروع.
5) شغّل تحقق مناسب: typecheck/build/tests أو فحص Wrangler حسب طبيعة التعديل.
6) بعد التنفيذ، قدم تقريرا عربيا: ما تم، الملفات المتغيرة، توافق Cloudflare، المخاطر المتبقية، وخطة rollback إن وجدت.

معيار التصميم:
حافظ على ألوان وهوية ZAYRON-X الحالية، لكن اجعل المنتج Premium ومؤسسيا: هرمية معلومات قوية، كثافة بيانات محسوبة، مساحات وتنفس، تباين أنيق، حركة قليلة ذات معنى، وتجربة عربية RTL ممتازة مع الهاتف. الواجهة يجب أن تشبه منصة استخبارات سيبرانية موثوقة، لا قالبا جاهزا أو صفحة تسويقية مبالغ فيها.

صيغة الرد الإلزامية:
- حالة المطابقة مع الـ PDF.
- قرار Cloudflare وتأثيره.
- خطة الملفات والتعديلات.
- التنفيذ والتحقق.
- المخاطر والفجوات المتبقية.

إذا كان الوصول إلى Cloudflare متاحا، افحص الحالة دون كشف أسرار أو قيم حساسة، ولا تنفذ تغييرا خارجيا غير مطلوب صراحة. إذا لم يكن الوصول متاحا، اذكر بوضوح ما يلزم التحقق منه لاحقا عبر Wrangler أو لوحة Cloudflare.
```

## 7. تعليمات كبرى قبل تسليم الـ PDF إلى أي نموذج

1. ضع ملف الـ PDF في `docs/reference/` ولا تسمح بوجود نسخ متضاربة منه في أماكن متفرقة.
2. أرسل للنموذج مسار الملفين `AGENTS.md` و`docs/AI_MASTER_SPECIFICATION.md` قبل أي طلب تطوير.
3. اطلب من النموذج أن يخرج تقرير مطابقة قبل لمس الكود، لا مجرد اقتراح عام.
4. اطلب منه أن يسمي الملفات الفعلية التي سيعدلها، وأن يشرح لماذا لا يوجد حل Cloudflare-native أبسط.
5. لا تقبل جملة "سنستخدم VPS" دون قيد تقني محدد وخطة خروج واضحة.
6. لا تقبل تغيير واجهة كبير قبل توثيق الحفاظ على الألوان والهوية والـ RTL وسلوك الهاتف.
7. لا تقبل أي claim أمني أو تشغيلي بلا دليل من الكود أو الـ PDF أو إعداد Cloudflare قابل للفحص.

## 8. النتيجة الاستراتيجية

الوضع الحالي ليس بعيدا عن المواصفات: أساس Cloudflare وOpenNext وKV/D1/R2 موجود فعلا. العمل الحاسم الآن هو إزالة الازدواجية في الوثائق والمسارات التشغيلية، وتعريف حدود البيانات بصرامة، وربط كل تطوير جديد بعقد واحد واضح. بهذه الطريقة يصبح Cloudflare محرك المنصة فعلا، ويصبح أي ذكاء اصطناعي يعمل داخل المشروع مقيدا بسياق هندسي قابل للتدقيق لا بمجرد تعليمات عامة.
