### 1.2 Why the application recorded `provider circuit open` — mechanism **verified**

`packages/intelligence/src/ai/adapter.ts` keeps a **process-local** circuit:

```js
const CIRCUIT_COOLDOWN_MS = { RATE_LIMITED: 60_000, TIMEOUT: 30_000, UNAVAILABLE: 30_000,
                              AUTH_FAILURE: 0, MODEL_FAILURE: 0, INVALID_REQUEST: 0, UNKNOWN: 0 };
providerCircuitOpen(p)  → true while now < blockedUntil
recordProviderHealth(p, failureClass) → opens the cooldown on failure; a SUCCESS deletes it
```

An `UNAVAILABLE` failure therefore blocks that provider for **30 seconds**. The ingest cron
(`*/10 * * * *`) dispatches a burst of ~20 analyses inside a couple of minutes, so **the first real
failure suppresses the rest of the burst**, and each suppressed request is recorded as a terminal
`FAIL` with `error_code = "provider circuit open"`.

**The triggering event is provable from the minute-level pairing** — one real Gemini error at the start of
each burst, then the rest of the burst rejected locally within the same minute:

| Minute | real Gemini `HTTP 503` | `provider circuit open` |
| --- | --- | --- |
| 04:31 | **1** | 3 |
| 04:32 | 0 | 10 |
| 04:33 | 0 | 18 |
| 04:34 | 0 | 16 |
| 04:51 | **1** | 3 |
| 04:52 | 0 | 15 |
| 04:53 | 0 | 21 |
| 05:02 | **1** | 5 |
| 05:03 | 0 | 17 |
| 05:04 | 0 | 18 |

13 bursts × ~20 analyses ≈ 268 circuit rejections generated by ~11 real Gemini errors. That arithmetic
matches the withheld set exactly: **268 circuit rejections + 19 unattributed + 8 real 503 + 2 timeouts +
1 truncated = 298**.

**Crucially, the amplification is not the damage.** Gemini completed **1 of 278** attempts today (0.4 %),
so had every suppressed attempt actually run, the measured expectation is **≈1** additional success — not
297. The outage is caused by *both providers failing at once*; the 30-second cooldown mainly made the
failures instant, uniform, and mis-attributed in telemetry.

### 1.4 Root cause chain (application layer — verified)

1. Cloudflare Workers AI fails **93 %** of CVE analyses today (`UNAVAILABLE`, origin unrecorded).
2. Automatic failover sends the request to Gemini, which fails **99.6 %** today (real `HTTP 503`
   "high demand", plus timeouts).
3. The first real Gemini failure opens a **30 s** cooldown; the remainder of the ~20-per-burst requests are
   rejected locally and persisted as `FAIL`/`error_code="provider circuit open"`.
4. With no model-authored analysis, persistence writes `REJECTED` + `WITHHELD` → the API returns
   `ANALYSIS_UNAVAILABLE` → the UI shows `ANALYSIS FAILED — PUBLICATION WITHHELD`.

### 1.5 Unresolved questions (explicitly not guessed)

- **Why Cloudflare returns `UNAVAILABLE` at 93 %.** The origin is not recorded: `event_trace.error_message`
  holds only `retry_count=N`, and there were **0** `QUOTA_EXHAUSTED` events today, so this is *not* the
  documented daily-allocation code. Resolving it requires either the origin-token telemetry (§2.3, now
  local) to be deployed, or provider-side account observability I do not have (billing/quota view).
- **Why Gemini returns `HTTP 503` "high demand" at 99.6 %.** That text is Google's; its cause is upstream
  and I made no provider call to probe it.
- Whether the 30 s cooldown cost any *recoverable* analyses on other days — today's measured answer is ≈1,
  but the cooldown interacted with different provider health on 10-11 (113 failures, 0 withheld).

## 2. Phase B — local-only safety fixes

### 2.1 `workers/ingest` deployment argument validation (the confirmed incident)

`workers/ingest/scripts/deploy-preview.mjs` previously tested **only**
`process.argv.includes("--dry-run")`, silently ignored every other flag, and spawned
`wrangler deploy --env preview` regardless. Added a strict `parseArgs`, run **before** anything can be
spawned, mirroring the API/Web entrypoints:

- `--dry-run`, `--env preview`, `--project-dir <dir>` are accepted;
- any other `--env` value → `REFUSED (WRONG_ENVIRONMENT_FLAG)`, exit 1;
- **any unknown flag** → `REFUSED (BAD_ARGUMENT)`, exit 1;
- a `ZAYRON_WRANGLER_BIN` seam was added, which is what makes "no deployment was started" provable.

**Before / after, the exact invocation that caused the incident, against the real workspace config:**

```
$ node scripts/deploy-preview.mjs --env production     # BEFORE: EXIT=0  and it DEPLOYED
$ node scripts/deploy-preview.mjs --env production     # AFTER:
[ingest-preview-deploy] REFUSED (WRONG_ENVIRONMENT_FLAG): --env 'production' is not allowed;
                        this entrypoint only deploys 'preview'
[ingest-preview-deploy] no deployment was started.
EXIT=1
```

The dry-run remains green (`target verified: zayron-x-ingest-preview -> zayron-x-preview-db &
zayron-ingest-queue-preview`, `EXIT=0`).

### 2.2 `workers/malware-validation` — fail-closed Preview-only route

That worker shipped `"deploy": "wrangler deploy"` while its top-level config binds the **production** report
store (`zayron-x-db`) and production R2, with a reconciliation cron — so any `deploy` reached production
bindings. Added, mirroring the API/Web guard pair:

- `scripts/preview-target-guard.mjs` — fail-closed evaluator: refuses a missing `[env.preview]`; requires
  the preview worker name; refuses production **and** validation D1 by name and by id; refuses the
  production/validation R2 bucket and requires `ARTIFACT_BUCKET`; refuses a non-empty preview cron (named
  environments inherit the top-level one); refuses `VALIDATION_MODE=true`. **No identity is invented** —
  the only database accepted is the already-approved `zayron-x-preview-db`.
- `scripts/assert-preview-target.mjs`, `scripts/deploy-preview.mjs` — strict `parseArgs` refusing any
  unknown flag or non-preview `--env` before spawning, plus `ZAYRON_WRANGLER_BIN` and `--project-dir` seams.
- `package.json` — added `guard:preview`, `deploy:preview`, `deploy:preview:dry-run` and made generic
  `deploy` refuse loudly; `dev`/`typecheck` untouched.

**Deliberate outcome:** the guard **refuses the worker's real `wrangler.toml`**, because no preview
artifact bucket is provisioned — a preview section would look deployable while pointing nowhere. A test
asserts that refusal, so the current state is *declared* rather than silently permitted.

### 2.3 Provider origin telemetry — the root cause of the diagnostic blindness

The interpretation boundary (`runGroundedInterpretation`) threw failures **without any origin marker**, and
its `recordAttempt` closure emitted attempts with **no `error_code` field at all**. So at that boundary a
local circuit rejection was indistinguishable from a real upstream error — the same blindness that hid 268
rejections from the operator live. Fixed at the cause (not by testing around it):

- the skip/circuit throw now carries `providerErrorCode: 'PROVIDER_SKIPPED' | 'CIRCUIT_OPEN'`, mirroring the
  CVE boundary; a caller-supplied `shouldSkipProvider` is deliberately left **unmarked** rather than
  mislabelled, and no new code is invented;
- `recordAttempt` now takes the thrown error and persists `error_code` via `providerAttemptErrorCode`.

All six failure sites in **both** boundaries now carry the origin (adapter.ts lines 820/869/900/1076/1121/1154);
the two `AUTH_FAILURE` sites have no error object and therefore record `null`, not a fabricated code.

### 2.4 Circuit lifecycle — review + **proposal** (not implemented, not deployed)

**Reviewed contract, now pinned by tests:** a transient `UNAVAILABLE`/`TIMEOUT`/`RATE_LIMITED` failure opens
a cooldown and suppresses later requests; `AUTH_FAILURE`/`MODEL_FAILURE`/`INVALID_REQUEST`/`UNKNOWN` open
**no** cooldown (a bad credential is never amplified into an outage); a success clears it; the only local
recovery lever is `__resetAIProviderCircuits()`.

**Design gap found:** the cooldown is a module constant and the clock is `Date.now`, so time-based recovery
**cannot be asserted in-process** — recovery is only testable through the reset lever. That is a testing
defect in the design, not just a missing test.

**Proposed bounded recovery (NOT implemented here, deliberately):**

1. make the cooldown table and clock injectable (`now?: () => number`) so recovery is testable without
   waiting;
2. **half-open single probe**: while open, admit exactly ONE probe per cooldown window rather than rejecting
   every caller;
3. **capped exponential backoff with jitter** on repeated trips (base 30 s → 60 s → 120 s, cap 5 min);
4. keep the durable `QUOTA_EXHAUSTED` contract as the ONLY cross-request switch; the circuit stays
   process-local and must never write durable state.

Acceptance tests to add with it: probe admitted exactly once per window; backoff doubles to the cap and not
beyond; a success resets the counter; an `AUTH_FAILURE` never opens a circuit; a probe failure never
establishes durable exhaustion.
**Honest priority note:** measured today, this recovers ≈1 of 297 withheld reports. It is a robustness and
observability fix, **not** the incident fix — provider health is. It should not displace §1.5.

### 2.5 Explicitly unchanged

The approved automatic failover policy is untouched: `AUTOMATIC_FAILOVER_CLASSES = { QUOTA_EXHAUSTED }`,
explicit provider preferences and the NVD authority route unchanged. Publication safeguards are untouched:
failed or deterministic fallback output is never published as model-authored analysis.
